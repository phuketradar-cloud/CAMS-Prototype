# Video Loop Generator

เครื่องมือแยกต่างหาก (ไม่เกี่ยวข้องกับระบบ CAMS) สำหรับสร้างวิดีโอลูปแบบไร้รอยต่อ (seamless loop) จากคลิปสั้น ทำงานทั้งหมดฝั่ง client ในเบราว์เซอร์ ไม่มีการอัปโหลดไฟล์ขึ้นเซิร์ฟเวอร์ และไม่ต้องใช้ API key ใด ๆ

## วิธีใช้งาน

เปิด `index.html` ในเบราว์เซอร์ (Chrome/Edge แนะนำ เพราะรองรับ `MediaRecorder` + `captureStream` ดีที่สุด) แล้ว:

1. อัปโหลด/ลากวางไฟล์วิดีโอต้นฉบับ (แนะนำคลิปสั้น 2–8 วินาทีที่มีการเคลื่อนไหวสม่ำเสมอ)
2. ตั้งค่าจำนวนรอบที่จะวนซ้ำ, ระยะเวลาผสานรอยต่อ (crossfade), FPS ของผลลัพธ์ (24–60) และคุณภาพ/บิตเรตของวิดีโอ (มาตรฐาน/สูง/สูงมาก/กำหนดเอง)
3. กด "สร้างวิดีโอลูป" แล้วรอประมวลผล
4. ดาวน์โหลดไฟล์ผลลัพธ์ (`.webm`)

## หลักการทำงาน

เครื่องมือนี้เป็นการประมาณผล (practical approximation) ของโจทย์ AI video-loop generation ต้นฉบับ (ดูข้อความเต็มได้ใน dropdown "เกี่ยวกับเครื่องมือนี้" ในหน้าเว็บ) โดยไม่ได้เรียกใช้โมเดล generative video ภายนอกใด ๆ เนื่องจากไม่มีบัญชี/API key ของผู้ให้บริการ (Runway, Veo, Kling ฯลฯ) ถูกระบุไว้ในโปรเจกต์นี้

เทคนิคที่ใช้แทน:

1. **Frame extraction** — วิดีโอต้นฉบับถูกแยกเป็นเฟรมภาพด้วย `<video>` + `<canvas>` ที่ FPS ที่กำหนด (สูงสุด 60 FPS)
2. **Auto seam search** — ค้นหาคู่เฟรมช่วงต้น/ท้ายที่คล้ายกันที่สุดเพื่อตัดต่อ แทนที่จะบังคับต่อเฟรมแรก/สุดท้ายเป๊ะ ๆ
3. **Motion-aware crossfade** — ประเมินการเลื่อน/ดริฟต์ของภาพระหว่างจุดต่อแล้วชดเชยตำแหน่งก่อนผสาน (alpha blend ด้วย smoothstep easing) ช่วยลดอาการภาพซ้อน (ghosting) ที่จุดวนลูป รวมถึงรอบสุดท้ายที่ผสานกลับไปยังเฟรมแรกสุด เพื่อให้เล่นวนซ้ำได้ไม่รู้จบ
4. **Re-encode** — ลำดับเฟรมที่ได้ถูกวาดลง canvas (ด้วย `imageSmoothingQuality: high`) แล้วบันทึกเป็นวิดีโอผ่าน `canvas.captureStream()` + `MediaRecorder` (WebM/VP9 เป็นค่าเริ่มต้น, ใช้ AV1 อัตโนมัติถ้าเบราว์เซอร์รองรับ) โดยกำหนด `videoBitsPerSecond` ตามคุณภาพที่เลือก (คำนวณจากความละเอียด×FPS หรือกำหนดบิตเรตเองเป็น Mbps) และจับเวลาวาดเฟรมแบบชดเชย drift เพื่อความแม่นยำที่ FPS สูง

## ข้อจำกัดของเวอร์ชันนี้

- ผลลัพธ์ยังไม่มีเสียง (video-only)
- การผสานภาพยังเป็น alpha blend + การชดเชยการเลื่อนแบบ global translation เท่านั้น ไม่ใช่ motion interpolation/optical-flow เต็มรูปแบบตามที่ prompt ต้นฉบับระบุ (ซึ่งต้องใช้โมเดล generative video) — สำหรับคลิปที่มีการเคลื่อนไหวเร็ว ซับซ้อน หรือมีหลายวัตถุเคลื่อนที่ต่างทิศทางกัน รอยต่ออาจยังสังเกตเห็นได้บ้าง
- การเพิ่ม FPS ผลลัพธ์ให้สูงกว่า FPS ของวิดีโอต้นฉบับ ไม่ได้เพิ่มรายละเอียดการเคลื่อนไหวจริง (ไม่มี frame interpolation) เป็นเพียงการสุ่มตัวอย่างเฟรมถี่ขึ้นเท่านั้น
- `videoBitsPerSecond` เป็นเพียงเป้าหมาย/เพดานที่ส่งให้ตัวเข้ารหัสของเบราว์เซอร์ ขนาดไฟล์จริงยังขึ้นกับเนื้อหาของวิดีโอด้วย
- Output เป็น `.webm` (จาก `MediaRecorder`); หากต้องการ `.mp4` ให้แปลงเพิ่มเติมด้วยเครื่องมือภายนอก เช่น ffmpeg
- แนะนำให้ใช้ Chrome หรือ Edge เนื่องจาก Safari รองรับ `canvas.captureStream()` ไม่สมบูรณ์
- FPS/คุณภาพสูงขึ้น = ใช้เวลาประมวลผลนานขึ้นและไฟล์ผลลัพธ์ใหญ่ขึ้น
